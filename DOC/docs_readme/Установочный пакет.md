
# Переменные окружения

Основные переменные (из `.env.example`):

| Переменная              | Описание         | Пример                    |
| ----------------------- | ---------------- | ------------------------- |
| `APP_ENV`               | Режим приложения | `dev` / `prod` / `test`   |
| `DATABASE_URL`          | asyncpg URL      | `postgresql://...`        |
| `SECRET_KEY`            | JWT-секрет       | `change-me`               |
| `MAX_CONNECTIONS_COUNT` | Пул asyncpg      | `10`                      |
| `MIN_CONNECTIONS_COUNT` | Пул asyncpg      | `10`                      |
| `POSTGRES_USER`         | Пользователь PG  | `conduit`                 |
| `POSTGRES_PASSWORD`     | Пароль PG        | —                         |
| `POSTGRES_DB`           | Основная БД      | `conduit_db`              |
| `POSTGRES_TEST_DB`      | Тестовая БД      | `conduit_test_db`         |
| `PACT_BROKER_URL`       | URL брокера      | `http://pact-broker:9292` |
| `GITEA_ADMIN_USER`      | Логин Gitea      | —                         |
| `GITEA_ADMIN_PASSWORD`  | Пароль Gitea     | —                         |
| `RUNNER_TOKEN`          | Токен act-runner | —                         |

В режиме `APP_ENV=test` специальный JWT-токен `valid-test-token` маппируется на пользователя `testuser` для Pact-верификации.

## Структура репозитория

```
├── backend/                 # FastAPI, миграции Alembic, unit-тесты
├── frontend/                # React (RealWorld Conduit)
├── tests/
│   ├── pact/consumer/       # Jest + Pact (consumer)
│   ├── pact/provider/       # Верификация на стороне провайдера (Python)
│   ├── e2e/                 # Playwright
│   └── api/                 # API-тесты Python
├── docker/
│   ├── app/                 # Dockerfile приложения, Nginx, supervisor
│   ├── db/                  # init-databases.sql
│   ├── gitea/               # app.ini, pipeline.yaml (канон workflow)
│   └── runner/              # Dockerfile и config act-runner
├── scripts/                 # 01-, 02-, 03-… автоматизация
├── workspace/               # Только .keep в Git; рантайм CI и bind-mount
├── .gitea/workflows/        # pipeline.yaml (копия из docker/gitea)
├── docker-compose.yml
├── .env.example
├── QUICKSTART.md            # Краткая шпаргалка на английском
└── README.md                # Этот файл
```



## Устранение неполадок

| Симптом | Что проверить |
|---------|----------------|
| Runner не берёт jobs | `docker compose logs act-runner`; сеть `docker network ls \| findstr conduit`; перезапуск после `02-setup-gitea.sh`. |
| `docker compose` в job недоступен | Образ раннера должен включать Compose-плагин; пересоберите `act-runner` (см. раздел 3 развёртывания). |
| Конфликт имени `conduit-app` при деплое | В пайплайне должен выставляться `COMPOSE_PROJECT_NAME` с существующего контейнера (актуальный `pipeline.yaml` из репозитория). |
| Push отклонён (non-fast-forward) | Повторите `03-push-code.sh` (в нём есть merge `gitea/main`) или вручную: `git fetch gitea && git merge gitea/main`. |
| Gitea «не должен работать от root» | См. [QUICKSTART.md](QUICKSTART.md) и полный сброс `scripts/00-reset-all.sh` при необходимости. |
| Порты заняты | Измените порты в `.env`, затем перезапустите стек. |

Подробнее по сценарию сброса Gitea и проверке пользователя `git` см. исторические заметки в англоязычных версиях документации в истории Git при необходимости.
